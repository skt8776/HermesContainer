# Researcher sharing contract

Purpose
- The researcher scans AI/vibe-coding trends daily.
- Only meaningful updates should be shared.
- Receiving teammates should record the update and convert it into role-specific implications.

Meaningful update criteria
- New workflow materially improves coding speed, review quality, or reliability
- New benchmark/eval materially changes which tools/models are worth using
- New agent/tool release is likely to affect this team's execution model
- New failure mode, safety issue, or regression pattern should change review or QA behavior
- New design-to-code or builder pattern clearly improves product development flow

No-send rule
- If no material update exists, do not broadcast anything.

Receiver obligations
- PM: record roadmap/PRD implications
- Designer: record UX/design-system implications
- Design Builder: record UI implementation implications
- Software Builder: record engineering/workflow implications
- Reviewer: record review criteria/risk implications
- QA: record test-matrix implications
